## What is Parameterized Testing?

Instead of writing 10 identical tests with different data, you write **one test** and drive it with a data table. This follows the DRY principle and makes your test suite much easier to maintain.

## Method 1: `test.each` — The Playwright Way

```typescript
import { test, expect } from '@playwright/test';

test.describe('Document Upload Validation', () => {
  
  // Define your test cases as an array
  const validDocTypes = [
    { type: 'Protocol', department: 'Clinical', expectedStatus: 'Draft' },
    { type: 'SOP', department: 'Regulatory', expectedStatus: 'Draft' },
    { type: 'Report', department: 'QA', expectedStatus: 'Draft' },
    { type: 'Specification', department: 'R&D', expectedStatus: 'Draft' },
  ];

  for (const { type, department, expectedStatus } of validDocTypes) {
    test(`can upload ${type} in ${department} department`, async ({ documentPage }) => {
      await documentPage.navigate();
      
      const docId = await documentPage.createDocument({
        title: `Test ${type}`,
        type,
        department,
        version: '1.0'
      });
      
      const status = await documentPage.getStatusBadge(docId).textContent();
      expect(status?.trim()).toBe(expectedStatus);
    });
  }
});
```

## Method 2: Data-Driven Validation Tests

```typescript
import { test, expect } from '@playwright/test';

// Test all invalid input combinations
const invalidInputs = [
  { title: '', expected: 'Title is required' },
  { title: 'A', expected: 'Title must be at least 5 characters' },
  { title: 'x'.repeat(256), expected: 'Title exceeds maximum length' },
  { title: '<script>alert("xss")</script>', expected: 'Invalid characters detected' },
];

for (const { title, expected } of invalidInputs) {
  test(`title validation: "${title.slice(0, 20)}..."`, async ({ documentPage }) => {
    await documentPage.navigate();
    await documentPage.openNewDocumentForm();
    await documentPage.titleInput.fill(title);
    await documentPage.submitButton.click();
    
    await expect(documentPage.titleError).toContainText(expected);
  });
}
```

## Method 3: JSON File-Based Test Data

For large datasets, store them in JSON files:

```json
// data/document-test-cases.json
[
  {
    "scenario": "SOP with single approver",
    "document": { "type": "SOP", "department": "Operations" },
    "expectedApprovers": 1
  },
  {
    "scenario": "Regulatory Protocol with two approvers",
    "document": { "type": "Protocol", "department": "Regulatory" },
    "expectedApprovers": 2
  },
  {
    "scenario": "Clinical Report with QA sign-off",
    "document": { "type": "Report", "department": "Clinical" },
    "expectedApprovers": 2
  }
]
```

```typescript
import { test, expect } from '@playwright/test';

import testCases from '../../data/document-test-cases.json';

for (const { scenario, document, expectedApprovers } of testCases) {
  test(scenario, async ({ documentPage }) => {
    await documentPage.navigate();
    const docId = await documentPage.createDocument(document);
    
    const approverCount = await documentPage.getRequiredApproverCount(docId);
    expect(approverCount).toBe(expectedApprovers);
  });
}
```

## Method 4: Boundary Value Analysis

A classic testing technique — test the edges of valid ranges:

```typescript
import { test, expect } from '@playwright/test';

const versionBoundaries = [
  { version: '0.1', valid: true, description: 'minimum valid version' },
  { version: '1.0', valid: true, description: 'normal version' },
  { version: '99.9', valid: true, description: 'high version number' },
  { version: '0.0', valid: false, description: 'version too low' },
  { version: '100.0', valid: false, description: 'version exceeds maximum' },
  { version: 'abc', valid: false, description: 'non-numeric version' },
  { version: '', valid: false, description: 'empty version' },
];

for (const { version, valid, description } of versionBoundaries) {
  test(`version boundary: ${description} (${version})`, async ({ documentPage }) => {
    await documentPage.navigate();
    await documentPage.openNewDocumentForm();
    await documentPage.versionInput.fill(version);
    await documentPage.titleInput.fill('Test Document');
    await documentPage.submitButton.click();
    
    if (valid) {
      await expect(documentPage.successMessage).toBeVisible();
    } else {
      await expect(documentPage.versionError).toBeVisible();
    }
  });
}
```

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
