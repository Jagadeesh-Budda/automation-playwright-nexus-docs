## The Whiteboard Evaluation

<Tabs>
  <Tab title="Execution Strategy">
    **What Interviewers Look For**: Do you understand Sharding vs Parallelism? 
    *   **Weak**: "I'll set `fullyParallel: true` in Playwright and run 50 workers on a single GitHub Actions runner." (Fails due to CPU bottleneck).
    *   **Strong**: "I will use CI Sharding. We will spin up 20 parallel Linux containers in GitHub Actions, passing `--shard=x/20` to Playwright, dropping execution time from 8 hours to 24 minutes."
  </Tab>

  <Tab title="Data Strategy">
    **What Interviewers Look For**: How do you prevent 200 parallel tests from modifying the same database record?
    *   **Weak**: "I'll write an `afterAll` script to delete the data." (Fails because parallel tests will collide before teardown).
    *   **Strong**: "I will use API Data Factories. Every `test.beforeEach` will make an API call to generate a unique, cryptographically random user (e.g., `user_8f3a@test.com`) so tests are hermetically isolated."
  </Tab>

  <Tab title="Artifact Strategy">
    **What Interviewers Look For**: Do you understand storage costs?
    *   **Weak**: "I will record a video and trace for every single test so we can debug easily." (Will consume terabytes of S3 storage per day and bankrupt the team).
    *   **Strong**: "I will set `trace: 'retain-on-failure'`. We only pay storage for tests that actually fail. Successful tests are discarded."
  </Tab>

  <Tab title="Tradeoffs">
    **What Interviewers Look For**: Senior engineers know there is no "perfect" solution, only tradeoffs.
    *   **Sharding**: *Benefit*: Blazing fast execution. *Cost*: Drastically higher CI/CD infrastructure compute costs.
    *   **API Factories**: *Benefit*: 100% data isolation. *Cost*: Requires deep dependency on backend APIs, making tests brittle to backend outages.
    *   **Retain-on-failure**: *Benefit*: Cheap S3 storage. *Cost*: You lose the ability to review historical traces of successful runs for performance profiling.
  </Tab>

  <Tab title="Model Senior Configuration">
    ```typescript
    // The resulting config demonstrating the strategy
    import { defineConfig } from '@playwright/test';

    export default defineConfig({
      fullyParallel: true,
      workers: process.env.CI ? 4 : undefined,
      retries: process.env.CI ? 2 : 0,
      reporter: process.env.CI ? [['github'], ['blob']] : [['html']],
      use: {
        trace: 'retain-on-failure',
        video: 'on-first-retry',
        baseURL: process.env.STAGING_URL || 'http://localhost:3000',
      },
    });
    ```
  </Tab>
</Tabs>
