This template focuses entirely on **Metrics and Reporting**. It is heavily pre-configured with Allure Reports, Slack Webhook integrations, and GitHub Actions telemetry.

## The Architecture

<Tabs>
  <Tab title="Why This Template?">
    **The Problem**: Flaky tests are ignored because the standard HTML report doesn't track historical failure rates or alert the team in real-time.
    
    **The Solution**: This template integrates Enterprise-grade observability tools. 
    *   **Allure Reports**: Generates beautiful, trend-tracking dashboards that show failure history over time.
    *   **Custom Slack Reporter**: A custom Playwright reporter class that POSTs a summary message to a Slack channel only if the build fails.
    *   **CI/CD Ready**: Includes a massive `.github/workflows/main.yml` configured for 20-worker sharding.
  </Tab>

  <Tab title="Directory Structure">
    ```text
    my-reporting-tests/
    ├── playwright.config.ts      # Configured with multiple custom reporters
    ├── .github/
    │   └── workflows/
    │       └── e2e.yml           # GitHub Actions sharding matrix
    ├── src/
    │   └── reporters/            
    │       └── SlackReporter.ts  # Custom class implementing Reporter interface
    ├── tests/
    │   └── telemetry.spec.ts     
    └── package.json              # Includes allure-playwright
    ```
  </Tab>

  <Tab title="The Custom Slack Reporter">
    Playwright allows you to write custom reporters. This template includes a script that intercepts the `onEnd` event to ping your team.

    ```typescript
    import { Reporter, FullResult } from '@playwright/test/reporter';
    import fetch from 'node-fetch';

    export default class SlackReporter implements Reporter {
      async onEnd(result: FullResult) {
        if (result.status === 'passed') return; // Only alert on failures

        const payload = {
          text: `🚨 *Nightly E2E Failed!* 🚨\nStatus: ${result.status}\nDuration: ${result.duration}ms\n<https://github.com/org/repo/actions|View Logs>`
        };

        await fetch(process.env.SLACK_WEBHOOK_URL!, {
          method: 'POST',
          body: JSON.stringify(payload)
        });
      }
    }
    ```
  </Tab>

  <Tab title="Enterprise Monitoring">
    True observability goes beyond HTML reports. It requires longitudinal trend monitoring.
    
    **Playwright ➡️ Reporter ➡️ DataDog ➡️ Dashboard ➡️ Alerting**

    This template is built to extract key metrics on `onEnd` and POST them to Enterprise Telemetry systems like **DataDog** or **New Relic**, allowing teams to monitor:
    *   **Failure Rate**: Is the `main` branch getting unhealthier over the past 30 days?
    *   **Execution Duration**: Did a recent dependency upgrade slow the test suite down by 5 minutes?
    *   **Flake Percentage**: Tracking which specific test IDs exhibit the highest standard deviation in results.
  </Tab>

  <Tab title="When NOT To Use">
    **Senior Engineers understand tradeoffs.** Do not use this heavy Observability Template if:
    *   You are a solo engineer hacking on a side project.
    *   You do not have a CI/CD pipeline (e.g., GitHub Actions, Jenkins) running your tests headless in the cloud.
    *   Your company does not use Slack/Teams or centralized telemetry tools.
  </Tab>
</Tabs>
