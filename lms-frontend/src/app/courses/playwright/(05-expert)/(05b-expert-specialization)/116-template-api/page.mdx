Welcome to the **Enterprise Templates Track**. This track bridges the gap between learning and doing. The templates provided here are production-ready boilerplates that you can immediately scaffold into your company's repositories.

This template is designed specifically for **Pure API Testing**. It does not use Playwright's browser engines. It relies solely on `request` contexts to perform blazing-fast microservice validation.

## The Architecture

<Tabs>
  <Tab title="Why This Template?">
    **The Problem**: Many SDETs try to test APIs using Postman or RestAssured, leading to fragmented tooling if the rest of the team uses TypeScript.
    
    **The Solution**: This template uses Playwright's `APIRequestContext` to run headless, Node.js-native API requests. 
    *   **Speed**: It can execute 500 API tests in under 10 seconds.
    *   **Auth Caching**: It uses a `global-setup` script to fetch a JWT token once, and caches it to the `storageState.json` so individual tests don't have to authenticate.
    *   **Schema Validation**: It comes pre-installed with `zod` for strict JSON payload validation.
  </Tab>

  <Tab title="Directory Structure">
    ```text
    my-api-tests/
    ├── playwright.config.ts      # Configured for 0 workers, no browsers
    ├── global-setup.ts           # Fetches & caches JWT tokens
    ├── package.json              # Includes 'zod' and 'dotenv'
    ├── .env                      # API_URL, CLIENT_ID, CLIENT_SECRET
    ├── src/
    │   ├── clients/              # API Client wrappers (e.g., UserClient.ts)
    │   ├── schemas/              # Zod validation schemas
    │   ├── data/                 # JSON fixtures for POST requests
    │   └── middleware/           # API Resilience Layer
    │       ├── RetryMiddleware.ts
    │       ├── AuthMiddleware.ts
    │       └── LoggingMiddleware.ts
    └── tests/
        ├── auth.spec.ts          # Validates 401s and token refreshing
        ├── users.spec.ts         # GET/POST/PUT/DELETE flows
        └── graphql.spec.ts       # GraphQL query structure testing
    ```
  </Tab>

  <Tab title="Core Configuration">
    The key to this template is the `playwright.config.ts`. Notice that we don't define any browser projects.

    ```typescript
    import { defineConfig } from '@playwright/test';

    export default defineConfig({
      testDir: './tests',
      globalSetup: require.resolve('./global-setup'),
      use: {
        baseURL: process.env.API_URL || 'https://api.staging.internal',
        // Inject the cached JWT token into every test automatically
        storageState: 'state.json', 
        extraHTTPHeaders: {
          'Accept': 'application/json',
          'X-Automation-Suite': 'true'
        }
      },
    });
    ```
  </Tab>

  <Tab title="When NOT To Use">
    **Senior Engineers understand tradeoffs.** Do not use this Pure API Template if:
    *   Your primary risk is the UI rendering (e.g., a highly visual React dashboard).
    *   80% of your validation requirements are UI-driven.
    *   Your backend APIs are extremely brittle or lack staging parity.
  </Tab>
</Tabs>
