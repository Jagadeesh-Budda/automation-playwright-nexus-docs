## Hint 1: Starting the Project

Forgot the command to initialize Playwright?

```bash
npm init playwright@latest
```
Press Enter to accept all defaults (use TypeScript, etc).

## Hint 2: The Configuration File

Can't remember how to set the `baseURL`? 

Open `playwright.config.ts`. Look for the `use: { ... }` block. 

```typescript
// playwright.config.ts
export default defineConfig({
  testDir: './tests', // Tells Playwright where your tests live
  // ...
  use: {
    baseURL: 'https://demo.playwright.dev/todomvc/',
    trace: 'on-first-retry',
  },
});
```
If you set `baseURL`, your `page.goto()` calls in your tests or fixtures only need to be `await page.goto('/')`.

## Hint 3: Locating Todo Elements

Struggling to find the right `getByRole` for the Todo app?

- **The main input:** It has a placeholder. Try `getByPlaceholder('What needs to be done?')`.
- **The list items:** Try `getByTestId('todo-item')`.
- **The checkbox:** Inside a specific list item, look for `getByRole('checkbox')`.

## Hint 4: The Fixture Syntax

Forgot how to extend the base test? 

You need two things: a type definition, and the `base.extend<T>` function.

```typescript
import { test as base } from '@playwright/test';
import { TodoPage } from './pages/TodoPage';

type MyFixtures = {
  todoPage: TodoPage;
};

export const test = base.extend<MyFixtures>({
  todoPage: async ({ page }, use) => {
    // 1. Setup
    // 2. use()
    // 3. Teardown
  }
});

export { expect } from '@playwright/test';
```

## Hint 5: Using the Fixture

Remember, if you create custom fixtures, your test file MUST import `test` from your new fixture file, **not** from `@playwright/test`.

```typescript
// tests/todo.spec.ts

// ✅ DO THIS:
import { test, expect } from '../fixtures/baseTest';

// ❌ DO NOT DO THIS:
// import { test, expect } from '@playwright/test';
```

## Common Mistakes

- **Hardcoding Waits**: Using `page.waitForTimeout()` instead of waiting for an element's state.
- **Overly Broad Locators**: Using generic CSS selectors like `.button` that might break if multiple buttons are added. Always prefer user-facing attributes like `getByRole`.
- **Ignoring Errors**: Catching errors in try/catch blocks without failing the test or logging the reason.
