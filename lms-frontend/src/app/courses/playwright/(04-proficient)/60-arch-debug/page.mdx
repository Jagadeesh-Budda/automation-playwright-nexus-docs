## Architectural Debt: How It Accumulates

Architectural violations start small. An engineer is in a hurry and puts a selector directly in a test file. Another engineer copies that pattern. Six months later, the test suite is unmaintainable.

The AST Auditor prevents this by catching violations automatically. But you still need to understand how to recognize and fix them manually.

## Red Flag: Selectors in Test Files

```typescript
import { test, expect } from '@playwright/test';

// ? VIOLATION � locators in spec file
test('admin deletes a document', async ({ page }) => {
  // These locators belong in DocumentPage.ts
  await page.getByRole('row').filter({ hasText: 'DOC-001' })
    .getByRole('button', { name: 'Delete' })
    .click();
    
  await page.getByRole('button', { name: 'Confirm' }).click();
  await expect(page.getByText('Document deleted')).toBeVisible();
});
```

```typescript
import { test, expect } from '@playwright/test';

// ? CORRECT � locators extracted to Page Object
test('admin deletes a document', async ({ documentPage }) => {
  await documentPage.deleteDocument('DOC-001');
  await expect(documentPage.deletionSuccessMessage).toBeVisible();
});
```

## Red Flag: Test Logic in Page Objects

```typescript
import { test, expect } from '@playwright/test';

// ? VIOLATION � assertion in Page Object
export class DocumentPage {
  async approveDocument(docId: string) {
    await this.getActionButton(docId, 'Approve').click();
    
    // DON'T put expect() in a Page Object!
    await expect(this.getStatusBadge(docId)).toContainText('Approved'); // Wrong!
  }
}
```

```typescript
import { test, expect } from '@playwright/test';

// ? CORRECT � assertion stays in the test
export class DocumentPage {
  async approveDocument(docId: string) {
    await this.getActionButton(docId, 'Approve').click();
    await this.modal.confirm();
    // No assertion here � return a value if needed
  }
}

// In the test:
await documentPage.approveDocument('DOC-001');
await expect(documentPage.getStatusBadge('DOC-001')).toContainText('Approved');
```

## Red Flag: Layer Leaking

```typescript
import { test, expect } from '@playwright/test';

// ? VIOLATION � test imports a component directly (skips Page Object layer)
import { Modal } from '../../components/Modal';

test('modal closes on cancel', async ({ page }) => {
  const modal = new Modal(page);  // Shouldn't create components directly in tests!
  await modal.cancel();
});
```

```typescript
import { test, expect } from '@playwright/test';

// ? CORRECT � access components through the Page Object
test('modal closes on cancel', async ({ documentPage }) => {
  await documentPage.deleteButton.click();
  await documentPage.modal.cancel();
  await expect(documentPage.documentRow).toBeVisible();
});
```

## Refactoring Pattern: Extract and Delegate

When you find a violation, the fix is always the same pattern:

1. **Identify** the UI interaction in the test
2. **Create a method** in the Page Object that wraps it
3. **Replace** the raw interaction in the test with the Page Object method

```typescript
import { test, expect } from '@playwright/test';

// Before: Test has too much knowledge
test('search filters results', async ({ page }) => {
  await page.getByRole('searchbox').fill('Clinical');
  await page.keyboard.press('Enter');
  await expect(page.getByRole('progressbar')).toBeHidden();
  const count = await page.getByRole('row').count();
  expect(count).toBeLessThan(10);
});

// After: Properly delegated
// Page Object:
async searchDocuments(query: string) {
  await this.searchBox.fill(query);
  await this.page.keyboard.press('Enter');
  await expect(this.loadingSpinner).toBeHidden();
}

// Test:
test('search filters results', async ({ documentPage }) => {
  await documentPage.searchDocuments('Clinical');
  await expect(documentPage.tableRows).not.toHaveCount(0);
});
```

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
