## Architectural Requirements

To pass this Capstone, your repository must contain the following **4-Layer Enterprise Architecture**:

### 1. The Page Object Model (POM) Layer
You must construct a deeply nested Page Object architecture. 
*   **BasePage:** A custom class that wraps standard Playwright actions (click, fill) with automatic logging and custom retry mechanics.
*   **DomainPages:** Login, Dashboard, and Checkout pages that inherit from the `BasePage`.

### 2. The API / Hybrid Layer
UI testing alone is too slow for enterprise CI/CD. 
*   You must build an `APIRequestBuilder` utility.
*   Your tests must use `request.post()` to automatically generate test data (e.g., seeding a user account) in the `beforeEach` block, before the UI test even begins.

### 3. The Custom Fixtures Layer
The heart of Playwright extensibility.
*   Extend the base `test` object in a `fixtures.ts` file.
*   Inject your Page Objects directly into the test signatures (e.g., `test('Checkout', async ({ checkoutPage }) => { ... })`).
*   Implement a custom Fixture that captures browser console errors and fails the test automatically if an error is detected.

### 4. The Orchestration Layer
The framework is useless if it doesn't run in the cloud.
*   Write a complete `playwright.config.ts`.
*   Configure **Test Data Management** using `.env` files for `STAGING` and `PRODUCTION`.
*   Create a `.github/workflows/playwright.yml` file to execute tests on `push` to `main`, archiving the HTML reports.

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
