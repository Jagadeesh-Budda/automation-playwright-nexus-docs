## What is the Entity Layer?

The **Entity Layer** (Layer 4) is the data foundation of your test framework. It defines:
1. **Data shapes** (TypeScript interfaces) — what fields exist
2. **Data factories** — how to generate valid test data
3. **Data builders** — fluent APIs for building complex objects

Think of it as your test framework's **schema layer**.

## The Builder Pattern for Test Data

For complex objects, the Builder Pattern lets you construct test data fluently:

```typescript
// entities/DocumentBuilder.ts
import { Document, DocumentType, DocumentStatus } from './Document';

export class DocumentBuilder {
  private doc: Partial<Document> = {
    version: '1.0',
    status: 'Draft',
    type: 'Protocol',
    department: 'QA',
  };

  withTitle(title: string): this {
    this.doc.title = title;
    return this;
  }

  withStatus(status: DocumentStatus): this {
    this.doc.status = status;
    return this;
  }

  withType(type: DocumentType): this {
    this.doc.type = type;
    return this;
  }

  withDepartment(department: string): this {
    this.doc.department = department;
    return this;
  }

  pendingReview(): this {
    this.doc.status = 'Pending Review';
    return this;
  }

  approved(): this {
    this.doc.status = 'Approved';
    this.doc.reviewedBy = 'reviewer@example.com';
    this.doc.approvedBy = 'admin@example.com';
    return this;
  }

  build(): Partial<Document> {
    if (!this.doc.title) {
      this.doc.title = `Test Document ${Date.now()}`;
    }
    return { ...this.doc };
  }
}
```

## Using the Builder in Tests

```typescript
import { test, expect } from '@playwright/test';

import { DocumentBuilder } from '../../entities/DocumentBuilder';

test('approved documents cannot be deleted', async ({ documentPage }) => {
  let doc = new DocumentBuilder()
    .withTitle('Locked Approved Protocol')
    .withType('Protocol')
    .approved()
    .build();

  const docId = await documentPage.createDocument(doc);
  
  // Attempt to delete
  await documentPage.navigateTo(docId);
  
  // The delete button should not exist for approved documents
  await expect(documentPage.deleteButton).not.toBeVisible();
});
```

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
