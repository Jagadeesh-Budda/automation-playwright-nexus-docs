## What is Component Testing?

Component Testing (CT) lets you test **individual UI components** without running a full application. Instead of navigating through a login page, dashboard, and settings to test a date picker — you mount the date picker directly in an isolated browser.

```
E2E Test:        Full App ? Login ? Navigate ? Find Component ? Test It
Component Test:  Mount Component ? Test It
```

## When to Use Component Testing vs E2E

| Scenario | Component Test | E2E Test |

| Testing a multi-page workflow | ? | ? |
| Testing login ? upload ? sign flow | ? | ? |

## Setting Up Component Testing

> [!WARNING]
> Component Testing is currently **experimental** in Playwright. The API may change between versions.

```bash
# Install the CT package for your framework
npm install -D @playwright/experimental-ct-react    # React
npm install -D @playwright/experimental-ct-vue      # Vue 3
npm install -D @playwright/experimental-ct-svelte   # Svelte
```

### Configuration

```typescript
// playwright-ct.config.ts
import { defineConfig } from '@playwright/experimental-ct-react';

export default defineConfig({
  testDir: './tests/components',
  use: {
    ctPort: 3100,
    ctViteConfig: {
      // Your Vite config overrides here
    },
  },
});
```

## Writing Component Tests

### Basic Component Mount

```typescript
// tests/components/Button.spec.tsx
import { test, expect } from '@playwright/experimental-ct-react';
import { Button } from '../../src/components/Button';

test('button renders with correct text', async ({ mount }) => {
  let component = await mount(<Button label="Upload Document" />);
  
  await expect(component).toContainText('Upload Document');
  await expect(component).toBeVisible();
});

test('button calls onClick handler', async ({ mount }) => {
  let clicked = false;
  
  const component = await mount(
    <Button 
      label="Submit" 
      onClick={() => { clicked = true; }} 
    />
  );
  
  await component.click();
  expect(clicked).toBe(true);
});
```

### Testing with Props

```typescript
import { test, expect } from '@playwright/test';

test('disabled button cannot be clicked', async ({ mount }) => {
  let component = await mount(
    <Button label="Submit" disabled={true} />
  );
  
  await expect(component).toBeDisabled();
});

test('button shows loading spinner when loading', async ({ mount }) => {
  const component = await mount(
    <Button label="Save" loading={true} />
  );
  
  await expect(component.getByRole('progressbar')).toBeVisible();
  await expect(component.getByText('Save')).toBeHidden();
});
```

### Testing Event Handlers

```typescript
import { test, expect } from '@playwright/test';

test('form emits data on submit', async ({ mount }) => {
  let submittedData: { email: string; password: string } | null = null;
  
  const component = await mount(
    <LoginForm onSubmit={(data) => { submittedData = data; }} />
  );
  
  await component.getByLabel('Email').fill('test@example.com');
  await component.getByLabel('Password').fill('secret123');
  await component.getByRole('button', { name: 'Sign In' }).click();
  
  expect(submittedData).toEqual({
    email: 'test@example.com',
    password: 'secret123',
  });
});
```

### Testing with Children (Slots)

```typescript
import { test, expect } from '@playwright/test';

test('card renders children content', async ({ mount }) => {
  const component = await mount(
    <Card title="Document Details">
      <p>Protocol v2.0 — Approved</p>
    </Card>
  );
  
  await expect(component.getByRole('heading')).toContainText('Document Details');
  await expect(component.getByText('Protocol v2.0')).toBeVisible();
});
```

## Updating Props After Mount

```typescript
import { test, expect } from '@playwright/test';

test('counter updates when prop changes', async ({ mount }) => {
  const component = await mount(<Counter count={0} />);
  await expect(component).toContainText('Count: 0');
  
  // Update the prop
  await component.update(<Counter count={5} />);
  await expect(component).toContainText('Count: 5');
});
```

## Running Component Tests

```bash
# Run all component tests
npx playwright test -c playwright-ct.config.ts

# Run in headed mode
npx playwright test -c playwright-ct.config.ts --headed

# Run specific test file
npx playwright test -c playwright-ct.config.ts tests/components/Button.spec.tsx
```

## Limitations of Component Testing

| Limitation | Explanation |
|-----------|-------------|
| **No routing** | Can't test `useNavigate()` or `<Link>` without mocking |
| **No global state** | Redux/Zustand stores need to be provided as props or context |
| **No API calls** | Must mock or provide test data directly |
| **No auth context** | Must wrap with mock auth providers |
| **Experimental** | API may change between Playwright versions |
| **Limited framework support** | React, Vue 3, Svelte only (no Angular yet) |

## Component Testing vs E2E: The Pyramid

```
        /\
       /  \        E2E Tests (few, slow, high confidence)
      /    \       ? Full workflows, multi-page flows
     /------\
    /        \     Component Tests (many, fast, medium confidence)
   /          \    ? Individual components, form validation
  /            \
 /--------------\  Unit Tests (most, fastest, low confidence)
                   ? Pure functions, data transformations
```

Component testing fills the gap between unit tests (no browser) and E2E tests (full app). Use it when:
- You have a **component library** that's shared across multiple apps
- You want **fast feedback** on UI changes without running the full app
- You need to test **edge cases** in components that are hard to reach in E2E

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
