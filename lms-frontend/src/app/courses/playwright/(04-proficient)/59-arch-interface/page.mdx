## Why TypeScript in Test Automation?

Playwright is built in TypeScript. Using TypeScript properly in your test framework gives you:
- **Auto-complete** in VS Code — no more typos in field names
- **Compile-time errors** — catch bugs before tests even run
- **Self-documenting code** — interfaces describe the shape of your data
- **Refactoring confidence** — rename a field, TypeScript tells you every place to update

## Defining Data Interfaces

```typescript
// entities/User.ts
export interface User {
  id: string;
  email: string;
  name: string;
  role: 'admin' | 'reviewer' | 'viewer' | 'auditor';
```

## Using Interfaces in Page Objects

```typescript
import { test, expect } from '@playwright/test';

// pages/DocumentPage.ts
import { Document, DocumentStatus } from '../entities/Document';

export class DocumentPage {
  // Method signature uses the interface — self-documenting!
  async createDocument(doc: Partial<Document>): Promise<string> {
    await this.newDocumentButton.click();
    
    if (doc.title) await this.titleInput.fill(doc.title);
    if (doc.version) await this.versionInput.fill(doc.version);
    if (doc.fileType) await this.fileTypeSelect.selectOption(doc.fileType);
    
    await this.saveButton.click();
    
    // Return the newly created document ID
    const idText = await this.documentIdDisplay.textContent();
    return idText!.trim();
  }

  async filterByStatus(status: DocumentStatus) {
    // TypeScript ensures only valid status values can be passed
    await this.statusFilter.selectOption(status);
    await expect(this.loadingSpinner).toBeHidden();
  }
}
```

## Interface vs Type: When to Use Each

```typescript
// Use interface for objects you might extend/merge
interface PageObject {
  page: Page;
  navigate(): Promise<void>;
}

// Extend an interface
interface AuthenticatedPage extends PageObject {
  currentUser: User;
  logout(): Promise<void>;
}

// Use type for unions, primitives, and computed types
type BrowserName = 'chromium' | 'firefox' | 'webkit';
type TestStatus = 'passed' | 'failed' | 'skipped';
type FixtureMap<T> = { [K in keyof T]: T[K] };
```

## Generic Utility Types in Test Code

```typescript
// Partial<T> — make all fields optional (useful for test data)
const partialDoc: Partial<Document> = { title: 'Test Doc' };

// Required<T> — make all fields required
const fullDoc: Required<Document> = { /* all fields must be provided */ };

// Pick<T, K> — select specific fields
type DocumentSummary = Pick<Document, 'id' | 'title' | 'status'>;

// Omit<T, K> — exclude specific fields
type DocumentInput = Omit<Document, 'id' | 'uploadedAt' | 'uploadedBy'>;
```

## Type-Safe Fixture Definitions

```typescript
// fixtures/baseTest.ts
import { test as base } from '@playwright/test';
import { LoginPage } from '../pages/LoginPage';
import { DocumentPage } from '../pages/DocumentPage';

// Define the exact shape of your fixtures
interface AppFixtures {
  loginPage: LoginPage;
  documentPage: DocumentPage;
  testUser: User;        // Inject test data as a fixture
  cleanupIds: string[];  // Track created resources for cleanup
}

export const test = base.extend<AppFixtures>({
  loginPage: async ({ page }, use) => { await use(new LoginPage(page)); },
  documentPage: async ({ page }, use) => { await use(new DocumentPage(page)); },
  
  // Inject a test user based on config
  testUser: async ({}, use) => {
    const user: User = {
      id: 'test-user-1',
      email: process.env.ADMIN_USER!,
      name: 'Test Admin',
      role: 'admin',
      department: 'QA',
      isActive: true,
    };
    await use(user);
  },
  
  // Shared cleanup tracker
  cleanupIds: async ({}, use) => {
    const ids: string[] = [];
    await use(ids);
    // Teardown: delete all created resources
    for (const id of ids) {
      await fetch(`${process.env.BASE_URL}/api/documents/${id}`, { method: 'DELETE' });
    }
  },
});
```

## Common Mistakes

> [!WARNING]
> **Mistake 1: Brittle Implementation**  
> **Wrong:** Tightly coupling test data with page interactions.  
> **Correct:** Abstracting data and logic appropriately.  
> **Why:** Prevents tests from breaking when minor details change.

> [!WARNING]
> **Mistake 2: Missing Synchronization**  
> **Wrong:** Relying on implicit speeds or hardcoded sleeps.  
> **Correct:** Using web-first assertions for synchronization.  
> **Why:** Guarantees deterministic execution regardless of environment speed.
